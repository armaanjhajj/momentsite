6. THE ZONING SYSTEM
Query → code, step by step
Implemented in src/lib/scent/msi.ts, function msiFor(vec):

Project into the zoning subspace. toSubspace() takes the 48-dim unit vector, subtracts pcaMean, and projects onto pcaBasis (24 × 48). Result: a 24-dim point p.
Digit 1 (macro). Nearest of the root node's 10 ordered centroids, plus the runner-up (needed for edge detection).
Digit 2. Descend into that child node; nearest of its 10 centroids.
Digit 3. Descend again; nearest of its 10 centroids.
Digit 4. The depth-2 node carries a leaf array. Each leaf is { a: number[24], t: number[9] } — an axis and nine decile thresholds. Compute proj = dot(p, a) and count how many thresholds it exceeds. No mean is stored: the thresholds are quantiles of the raw projection, so a constant shift common to every point cancels out.
Assemble. zone = 1000·d₁ + 100·d₂ + 10·d₃ + d₄; code = 10000·sense + zone; label = "1·" + zeroPad(zone, 4).
Edge flag. If sqrt(secondD)/sqrt(bestD) < 1.18 at the macro level, report "sits near the edge of 1·Nxxx". Macro level only — a boundary that moves the last digit is not worth saying out loud.
Cells with fewer than 10 members get no leaf split and their fourth digit is 0.

What is stored per level
Level	Nodes	Stored
Root	1	10 centroids × 24 dims
Depth 1	≤10	10 centroids × 24 dims each
Depth 2	≤100	10 centroids × 24 dims each, plus 10 leaf splits (a: 24 floats, t: 9 floats)
Total 291 nodes. Plus macroNames (10), subNames (10×10), cellNames (10×10×10 = 1,000 strings), pcaMean (48), pcaBasis (24×48).

How names are generated now
Not from a cell's own member labels. Each node is named from the 40–160 atlas molecules nearest its centroid in the full 48-dim space, weighted by similarity⁶, scored by p_in × log(p_in / p_corpus) — prevalence inside times log-ratio against the corpus. Prevalence alone returns what is common everywhere; lift alone returns what is rare anywhere.

macroNames uses 160 neighbours and takes the top 2 joined by "and", deduplicated across all ten so the map legend has distinct entries. subNames (displayed as region) uses 80. cellNames (displayed as sub) uses 40, banned only against its own region's stem.

Displayed breadcrumb is senseName › region › sub, i.e. levels 2 and 3 — not the macro name, which survives only as the map legend.

What changed in the last revision, and why
Reported symptom: "new car" was labelled Vanilla and phenolic > Medicinal.

Three findings, in order of investigation:

Decomposition was correct. "new car" → plastic 1.00, leather 0.80, solvent 0.70, rubbery 0.55, waxy 0.45, sweet 0.35, confidence 1.00, from a single lexicon phrase match.
Position was correct. The query vector's nearest neighbours among all 5,548 atlas molecules were o-xylene (Cc1ccccc1C), p-cymene, α-methylstyrene, styrene, methylanisole, toluene, methylnaphthalene. Exactly right.
Naming was the bug. A leaf cell holds ~5 molecules, and GS-LF labels them sparsely: o-xylene carries only geranium, toluene only sweet. Counting labels over five such molecules is small-sample noise, and the cell named itself nutty. The macro name was worse — naming a macro is naming ~550 molecules, and vanilla was the top-lift term across a group that also contains styrene and naphthalene.
Three changes made:

Naming switched from member-label counting to centroid-neighbourhood scoring (above). This is the fix for the reported bug.
Fourth digit added, 1,000 → 10,000 zones. Deliberately not a fourth k-means level, which would have meant 10,000 more centroids and ~1 MB of JSON; the axis+thresholds scheme costs 33 numbers per cell instead of 240.
Zoning subspace 12 → 24 dims, chosen by measurement. Share of a molecule's true nearest neighbours landing in its own cell across subspace sizes 12/16/24/32: 38.2% / 39.5% / 44.2% / 44.0%. Macro-level agreement was flat at ~86% throughout, which is why the subspace was never the reason a macro name looked wrong. This change is what moved petrichor from Citrus > Floral to Camphoreous > Earthy, sharing a cell with geosmin itself.

7. TEXT TO POSITION
The path
src/lib/scent/decompose.ts → src/lib/scent/project.ts.

Lexicon match, three passes (decompose.ts:81): multi-word phrases longest-first with span consumption, then synonyms, then bare descriptor names. Returns { weights, matched, confidence } where confidence is the fraction of non-stopword input consumed.
LLM fallback fires when confidence < 0.6 (ASK_MODEL_BELOW, src/app/scent/page.tsx:31). Weights are merged with mergeWeights (max per descriptor).
Projection (project.ts:67): weights → TF-IDF weighted descriptor vector → multiply by components (48×87 descriptor directions) → unit-normalise.
Lexicon
src/data/scent/memories.ts, 34,266 bytes, 126 weight blocks. Hand-written.

When the LLM fires, and what it is asked
POST /api/scent/decompose is called on every query, not only low-confidence ones — it supplies the "What this is" identity card, which the page waits for before rendering anything. But its weights are used only when lexicon confidence < 0.6. Model: claude-sonnet-5, max_tokens: 1024, thinking: {type: "disabled"}, output_config.effort: "low", JSON-schema-constrained to the 87-descriptor vocabulary.

Caching
None. No cache layer at any level: no unstable_cache, no client memo across queries, no HTTP cache headers on the route. Every search is a fresh API call. Repeating the same search costs the same tokens again.

Determinism
For lexicon hits: yes, provably.


$ (three separate tsx invocations)
1·8680 | conf 1
1·8680 | conf 1
1·8680 | conf 1
"new car" matches a lexicon phrase at confidence 1.00, so the model's weights are discarded and the pipeline is pure arithmetic.

For lexicon misses: no. Below confidence 0.6 the code depends on Claude's returned weights, which are not temperature-zero-guaranteed and may differ run to run. The same typed input can therefore produce a different MSI on two occasions. This is not currently disclosed anywhere in the UI.

Also: codes are not stable across rebuilds. Regenerating embedding.json (which re-fits descriptor directions on a curated set that can change) or zones.json moves existing codes. Posts already in the database store the code computed at write time and are not re-zoned. Migration 20260728120000 acknowledges this in its header comment.

10. THINGS THAT WOULD EMBARRASS YOU

A chemist will challenge these:

Formaldehyde's SMILES is C=O. It parses and canonicalises correctly in RDKit, but it is a one-heavy-atom molecule being passed through a message-passing network that has essentially no graph to pass messages over. Its embedding should be treated as unreliable. It was added today and its position has not been sanity-checked.
The five added VOCs are absent from GS-LF entirely — toluene, xylene, ethylbenzene and formaldehyde are not in the atlas, because GoodScents/Leffingwell is a flavour-and-fragrance archive. Their descriptors are hand-assigned by me from general knowledge, not from a curated perceptual source. Their embeddings come from the GNN, but the labels driving their retrieval are my assertions.
Descriptor weights throughout memories.ts are hand-tuned by me, not derived from data. "New car = plastic 1.00, leather 0.80, solvent 0.70" is a judgement call presented alongside measured quantities in the same UI.
Detection thresholds on molecule cards are hand-entered from literature I did not cite. No source is recorded for any of them.
Stereochemistry. The enantiomer ratio 0.2025 is real and measured, and both carvones ship as separate entries. But that ratio means enantiomer pairs sit at 20% of random-pair distance — i.e. the model does not separate them the way perception does. The page frames this as a named blind spot, which is honest, but a reviewer may read the number as a claim of success. It is a claim of failure, correctly disclosed.
An ML researcher will challenge these:

Snitz was measured on 256-dim vectors; the site ships 48-dim. Not re-measured after PCA. See §4.
77 pairs, 50 molecules. That is a small evaluation set for a headline correlation. The permutation test (10,000 permutations, p ≈ 1e-4) addresses significance, not power.
The Morgan baseline is one baseline. No comparison against a count-based fingerprint, a physicochemical-descriptor model, or a random-projection control.
The 44.2% cell-fidelity figure has a ceiling. A cell holds ~5.5 molecules on average, so at most ~5 of a molecule's 10 nearest neighbours can possibly share it. 44.2% against a ~50% ceiling is good; quoted bare, it reads as poor. Always quote the ceiling with it.
No held-out evaluation of the naming change. The naming fix was validated against 12 hand-chosen probe queries that I selected, several of which I had already seen fail. That is iterative tuning on the evaluation set, not a held-out test.
The subspace sweep (12/16/24/32) was scored on one metric across one random sample of 400 molecules with a fixed seed. Not repeated across seeds.
explainedVariance: 0.9945 is PCA retention from 256 → 48, not a measure of how well the embedding captures perception. Do not let it be read as the latter.
A hiring manager will challenge these:

None of it is committed to git. No history, no diffs, no ability to prove when anything was written or to revert. A single overwrite destroys provenance — which is exactly what happened to the pre-20:00 embedding.json.
Training is unreproducible in practice. No logs, no recorded epoch count, no seed captured in the checkpoint metadata that I have verified, no wall-time. best.pt exists and its metrics exist, but the run that produced it cannot be reconstructed from the repo.
npm run scent:build is a live footgun pointing at the superseded estimator.
A 2.5 MB file sits in public/ that nothing fetches.
/scent first-load is 257 kB, of which ~247 kB is zones.json inlined into the client bundle. The MSI lookup could run server-side; it does not.
Rate limiting on /api/scent/post is an in-memory Map keyed by IP (route.ts:29). On serverless, each instance has its own counter, so the effective limit is 8 × instance count. It stops a hammering tab, not a determined actor.
The /api/scent/decompose call happens on every search with no caching, so token spend scales linearly with searches including repeats — after an explicit instruction earlier in the project to keep API cost low.
